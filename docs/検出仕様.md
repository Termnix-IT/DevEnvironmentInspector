# 検出仕様

## カタログと探索範囲

カタログは`catalog/tools.json`をビルド時に埋め込む。外部ファイルを自動読込しない。カテゴリは`runtime`、`ai_cli`、`development`、`package_manager`の4種類である。

| ツール | コマンド | バージョン取得引数 |
| --- | --- | --- |
| Node.js | `node` | `--version` |
| Python | `python`, `python3` | `--version` |
| Java | `java` | `-version` |
| Go | `go` | `version` |
| Rust | `rustc` | `--version` |
| Codex CLI | `codex` | `--version` |
| Claude Code | `claude` | `--version` |
| Gemini CLI | `gemini` | `--version` |
| Git | `git` | `--version` |
| Docker CLI | `docker` | `--version` |
| Terraform | `terraform` | `--version` |
| AWS CLI | `aws` | `--version` |
| kubectl | `kubectl` | `version --client=true --output=json` |
| npm | `npm` | `--version` |
| pnpm | `pnpm` | `--version` |
| pip | `pip`, `pip3` | `--version` |
| uv | `uv` | `--version` |
| WinGet | `winget` | `--version` |

実行引数はRustコードの許可リストに固定し、カタログJSONから引数・シェル文を指定できない。スキーマ不一致、未知コマンド、重複ID・コマンド、不正な識別子を拒否する。

PATHはプロセス環境変数から読み、絶対ローカルパス内の固定ファイル名だけを確認する。ディレクトリを再帰走査しない。空要素、相対パス、`..`を含むパス、UNC・デバイス形式のパスは除外する。カレントディレクトリは暗黙に検索しない。PATH未設定時にはこの情報源の候補はない。

PATHEXTのうち`.COM`、`.EXE`、`.BAT`、`.CMD`だけを順序通りに使用し、未設定時はこの順を使う。未対応拡張子は診断へ記録する。PowerShellの関数、エイリアス、`.ps1`、関連付けによる実行は対象外であり、シェルの完全なコマンド解決を再現するものではない。

PATHの重複ディレクトリは除外する。同じコマンドと同じパスの情報を統合し、PATH順・拡張子順を維持する。パス比較では構成要素を分け、ASCIIの大文字小文字を無視する。シンボリックリンクの実体、8.3短縮名、非ASCII文字の大文字小文字が異なる同一パスの統合は未対応である。

## Windows追加情報源

CLIとMCPは既定で次の情報源も使う。`--path-only`はPATHのみへ制限する。検出用の製品名、パッケージID、相対配置は`catalog/windows.json`へ埋め込み、外部カタログや任意の探索パスを受け付けない。

| 情報源 | 読み取り範囲と判断 |
| --- | --- |
| `installed_applications` | HKCU / HKLMの`Software\Microsoft\Windows\CurrentVersion\Uninstall`を32・64ビットビューで確認。既知のDisplayNameに完全一致、または数字で始まるバージョン接尾辞が付く製品だけを対応付ける |
| `winget` | 同じ登録の`WinGetPackageIdentifier`が既知IDに一致する場合。`DisplayVersion`、`InstallLocation`、portableの`PortableTargetFullPath`を利用。WinGet導入方式を示す根拠はこの明示マーカーとし、製品名・配置だけでは推測しない |
| `registry` | HKCU / HKLMのPythonCore（PEP 514）のInstallPath・ExecutablePath、JavaSoftのJDK / Java Development Kit / Java Runtime EnvironmentのJavaHome、GitForWindowsのInstallPath、GoProgrammingLanguageのinstallLocation |
| `npm_global` | `%APPDATA%/npm`、Program Files内のnodejs、許可済みPATHディレクトリをprefix候補とし、`node_modules`内のnpm、pnpm、@openai/codex、@anthropic-ai/claude-code、@google/gemini-cliのpackage.jsonだけを読む |
| `known_directory` | Program Filesのnodejs、Git/cmd、Go/bin、Docker/Docker/resources/bin、Amazon/AWSCLIV2、JavaとEclipse Adoptiumのjdk接頭辞フォルダー、LocalAppDataのPrograms/PythonのPython3接頭辞フォルダーとMicrosoft/WindowsApps、ユーザーホームの.cargo/binと.local/bin（uv、claude、codex） |

レジストリは読み取り権限だけで開く。`UninstallString`、`ExecutableArguments`、認証設定は読まない。`Win32_Product`、WinGet CLI、npm CLIの起動は行わない。WinGetのオンラインソース照合、MSIX全体の列挙、独自WinGet保存先の探索、WinGet導入の網羅的な履歴取得は未対応である。WinGetで導入されたMSI製品でも明示マーカーがなければ導入方式は未確定になる。

npmはpackage名の一致と短いバージョン形式を検証する。binはパッケージ内の相対パスとして解釈し、絶対パス・`..`を拒否する。既知コマンド名のネイティブbin、およびそのパッケージのbin参照を含むprefix直下のcmdラッパーだけを候補にする。JSファイル自体は実行候補にせず、登録情報として残す。package.jsonのscriptsは実行せず、`.npmrc`やトークンは読まない。Node同梱の場合があるnpm本体の導入方式は未確定にする。独自prefixがPATHにも既知配置にもなければ検出対象外である。

既知ディレクトリの探索は固定ファイル名、または指定フォルダーの子1階層だけである。子のsymlink / junctionは階層探索しない。メタデータ読込では解決後のUNCを拒否するが、マップされたネットワークドライブやOS呼出しの厳密な時間隔離までは保証しない。

製品登録は`registrations`へ、存在確認できた実行ファイルは`installations`へ保存する。登録だけではCLIが使えるとしない。製品登録は同じ観測キーに限り統合し、生キー名を公開せずスキャン内IDへ置き換える。32・64ビットビューや別キーの登録を、製品名だけで同一実体と推測して統合しない。実行候補はコマンド名とパスが一致した場合だけ情報源を統合する。別パスのPATH候補に登録情報のバージョンや導入方式を転記しない。

## 検出と診断

ファイルの存在を確認できた実体だけを実行候補にする。通常ファイルと確認できても読み取りが拒否された場合は`access: denied`とする。存在確認自体が拒否された場合は取得失敗とし、架空の候補を作らない。別途製品登録を確認できた場合は登録情報を保持する。読取可否は実行権限の保証ではない。

| 状態 | 意味 |
| --- | --- |
| `not_found` | 実施した情報源の探索範囲で候補なし。未インストールの断定ではない |
| `detected` | 少なくとも1実行候補または製品登録を確認。バージョンや利用可否の成功を意味しない |
| `incomplete` | 取得失敗、対象の除外、候補上限等によって探索が不完全。候補を併せて保持する場合がある |

`fact`は確認した存在、重複、アクセス拒否、プローブ結果等を表す。`caution`は未確認事項を表す。たとえば、バージョン未取得時の利用可否や、ラッパー自体を実行していないことは注意事項にする。

同名コマンドの複数候補は`multiple_command_candidates`として`info`で記録する。PATH上の優先候補のネイティブ実行に成功した場合だけ`cli_available`を記録し、後続候補の成功で優先候補の失敗を隠さない。これは今回の環境変数・空の作業ディレクトリで固定引数が成功した事実であり、すべてのCLI操作が利用可能という保証ではない。

同じ実体の申告バージョンと実測値が異なる場合は`conflicting_version_evidence`とする。異なる実体のバージョン差を異常扱いしない。登録があるのに実行候補がない場合は`registered_executable_unresolved`、そのツールのPATH候補がない場合は`registered_tool_not_on_path`を`caution`として残す。登録だけでは存在しない理由を確定できないためである。製品名と別ツールの明示パッケージIDが矛盾する場合は`metadata_invalid`で不完全とし、製品名による対応付けを採用しない。

バージョンの純粋な数値列で末尾の`.0`だけが異なる場合や、Gitの`.windows.N`表記だけが異なる場合は`version_format_difference`を`caution / info`として記録し、矛盾の警告にしない。これは同一バージョンの断定ではなく表記上の差の可能性を示す処理であり、元の申告値を両方保持する。それ以外の文字列差も申告値が食い違う事実を示すもので、どちらが正しいかまでは決めない。

## バージョン取得と実行制限

既定のスキャンはファイルと登録メタデータの確認のみ。`--probe-versions`を明示した場合に限り、検出済みの候補を逐次実行する。

| 制限 | 既定値 | ライブラリが許容する最大値 |
| --- | --- | --- |
| PATH入力要素 | 先頭256要素 | 256 |
| 保持候補 | 各ツール16件 | 16 |
| 保持する製品登録 | 各ツール16件 | 16 |
| ARP子キー | 各hive・ビュー1024件 | 合計4096件 |
| Python / Javaバージョン子キー | 各既知キー64件 | 64件 |
| レジストリ値 | キー内の最大値が16 KiB以下、文字列8 KiB以下 | 同左 |
| npm prefix | 256件 | 256件 |
| package.json / npmラッパーの受動読込 | 256 KiB / 16 KiB | 同左 |
| 既知配置 / 子1階層列挙 | 128配置 / 各128エントリー | 同左 |
| バージョン実行 | 全体64回 | 64 |
| 1実行の待機時間 | 2秒 | 5秒 |
| スキャンの処理予算 | 30秒 | 60秒 |
| stdout / stderr | 各16 KiB | 各16 KiB |
| 終了処理の追加待機 | 1秒 | 1秒 |
| ラッパー読込 | 8 KiB | 8 KiB |
| JSON読込・保存 | 8 MiB | 8 MiB |

スキャン予算が尽きた後は新たなプローブを開始しない。終了処理の待機は予算の外に最大1秒追加される。標準ファイルI/Oやプロセス作成のOS呼出しには厳密な時間保証がないため、スキャン全体の壁時計時間を保証するハードタイムアウトではない。マップされたネットワークドライブやリンク先を含む遅いファイルシステムの隔離は未実装である。

実行ファイルはカタログのコマンド名と一致する絶対パスだけを受け付け、引数は配列で渡す。標準入力は閉じ、作業ディレクトリは新しい空の一時ディレクトリにする。環境変数はOS・ユーザーディレクトリ・PATH等の限定された項目だけを引き継ぎ、認証変数や`NODE_OPTIONS`等を引き継がない。更新通知やCorepack・rustupの自動取得を抑止する変数を設定する。

Windowsでは起動直後のプロセスを一時停止状態でJob Objectに割り当ててから実行する。時間超過・出力超過・読取失敗時はJob Object全体を終了し、終了待ちにも上限を設ける。後処理失敗は`cleanup_failed`とし、成功と報告しない。これらはプロセス管理であり、起動したプログラムのネットワークやファイル操作を遮断するサンドボックスではない。

### npmラッパー

`.cmd`はシェルで実行しない。npm/cmd-shim形式の`"%_prog%"`呼出しに、許可された固定の`%dp0%`相対パスと`%*`だけが続く場合、その起動先を認識する。同じディレクトリの`node.exe`を優先し、なければPATHの優先Node候補を使う。相対スクリプトを実行引数としてNodeへ直接渡す。

| コマンド | 固定起動先 |
| --- | --- |
| npm | `node_modules/npm/bin/npm-cli.js` |
| pnpm | `node_modules/pnpm/bin/pnpm.cjs` |
| Codex | `node_modules/@openai/codex/bin/codex.js` |
| Claude | `node_modules/@anthropic-ai/claude-code/cli.js` |
| Gemini | `node_modules/@google/gemini-cli/dist/index.js` |

この処理はラッパー中の他の文を評価せず、ラッパー全体の等価実行や正当性を保証しない。取得結果の`source`は`npm_entrypoint`とし、`wrapper_not_executed`を付ける。未知形式、Corepack等の別構造、`.bat`は検出だけ行い、バージョンは`unsupported_wrapper`とする。インストール方式を`npm`と確定する根拠にはしない。

## 出力と保存

バージョンは既知のバナー位置から短い文字列だけを抽出する。Javaのstderr、kubectlの`clientVersion.gitVersion`にも対応する。パス等を含む生のstdout・stderrは保存・ログ出力しない。未知の出力、非ゼロ終了、時間超過、出力超過、権限不足を別の状態で返す。

保存JSONは`schema_version: 2`で、日時はUTCのRFC 3339。旧スキーマ1は読込時に空の`registrations`を補ってメモリー上で2へ移行し、元ファイルを自動更新しない。未知スキーマ、壊れたJSON、サイズ超過、存在しない診断参照、矛盾する検出状態等を拒否し、破損データを暗黙に空データへ置き換えない。アトミック置換とパス公開設定は[アーキテクチャ](アーキテクチャ.md#保存と公開範囲)を参照する。

## テストの範囲

モックで未検出、PATHの順序と重複、存在確認の拒否、読取拒否、プロバイダー失敗、情報の矛盾、候補数・プローブ数・時間予算を検証する。一時領域の実行ファイルでUnicode・空白・シェル特殊文字を含むパス、固定起動先の引数、出力超過、失敗終了、継承されたパイプを持つ子プロセスの終了、環境変数の制限を検証する。JSONは保存と再読込、置換失敗時の保持、破損・未知スキーマ・サイズ超過・公開範囲を検証する。

実際の18製品それぞれのインストール形態や全バージョンを実機確認したものではない。バナー形式が変わった場合は`unrecognized_output`になり、既存形式のフィクスチャを追加して解析を更新する。MCPクライアントとの通信・応答・実行制限の検証は[MCP連携](MCP連携.md#互換性と検証)を参照する。

Windows追加検出はレジストリ観測のモックと一時フォルダーのpackage.json・ダミー実行ファイルで検証する。登録だけの検出、明示WinGetマーカー、複数バージョン、同一パスの情報矛盾、権限拒否、壊れた・過大なJSON、binのパス逸脱、無関係なラッパー、1階層の探索制限、登録パスの秘匿、旧保存形式の移行を含む。実機のレジストリ書き換えや製品のインストールは行わない。

参照：[npm cmd-shim](https://github.com/npm/cmd-shim)、[rustupの環境変数](https://rust-lang.github.io/rustup/environment-variables.html)。
